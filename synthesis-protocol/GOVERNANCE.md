## How to Contribute

### For documentation, examples, and tooling

1. Fork the repository
2. Create a branch: `git checkout -b your-contribution-name`
3. Make your changes
4. Run the integrity check: confirm your contribution does not modify any constitutional file without explicit intent
5. Submit a pull request with:
   - A clear description of what you changed and why
   - An honest statement of which Pou your contribution honours
   - Attribution for any external knowledge or thinkers you drew from (Pou I — Whakapapa as Anchor)

### For constitutional files

Open an issue first. Describe the proposed change, the constitutional grounds for it, and which Pou it serves or strengthens. Peter Makara will respond. Do not submit a pull request modifying constitutional files without prior issue discussion.

## The Dignity Check

Before submitting a contribution, ask yourself:

1. **Does this honour the North Star?** — *In 10,000 years, a 10-year-old child flourishes in joy, safety, connection, and mauri.*
2. **Does this preserve dignity?** — For all people referenced, affected, or involved (Pou III)
3. **Does this carry its whakapapa honestly?** — Is the source of every idea attributed? (Pou I)
4. **Does this return more than it takes?** — Does this contribution enhance the ecosystem or extract from it? (Pou IV)

If the answer to any of these is uncertain, open an issue and ask before contributing. That is not weakness — it is manaakitanga.

## Versioning

All contributions must be consistent with the Semantic Versioning scheme in `RELEASE.md`:

- `PATCH` — documentation fixes, example improvements, typo corrections
- `MINOR` — new tooling, new examples, non-constitutional additions
- `MAJOR` — any change to a constitutional file (requires Peter Makara's direct review)
